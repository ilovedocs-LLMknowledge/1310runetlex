# Договоры в Word: протокол разногласий и итоговая редакция

В программе три вкладки.

1. **Протокол разногласий.** Правки контрагента, сделанные в режиме рецензирования Word, превращаются в протокол разногласий по шаблону.
2. **Итоговая редакция.** Обратная задача. На входе исходный договор и протокол разногласий (в Word или скан) и/или допсоглашения. На выходе договор в итоговой редакции, где все изменения показаны правками Word. Автор каждой правки — документ-источник, например «Протокол разногласий» или «ДС № 2 от 15.10.2026». Поэтому в Word их можно принимать и отклонять по документам.
3. **История.** Список всех прогонов. Для каждого прогона доступны кнопки «Открыть результат» и «Показать в Finder».

Программа понимает автонумерацию Word, а также номера, набранные текстом.

## Запуск (Mac)

Нужен Python 3, сторонние библиотеки не нужны.

- Дважды щёлкните **`Запустить.command`** (при первом запуске: правая кнопка → «Открыть»), или
- в Терминале выполните `python3 protocol_app.py`.

Откроется страница в браузере. Если программа уже была запущена, закройте старое окно Терминала и запустите её заново, иначе откроется старая версия.

Есть и вариант без установки: файл **`Протокол разногласий.html`**. В нём только вкладка «Протокол разногласий». Страница работает полностью офлайн: ей запрещены любые сетевые запросы.

## Что и куда уходит

- **Протокол разногласий** и **протоколы в Word с таблицей** обрабатываются только на компьютере.
- **Сканы** (PDF, JPG, PNG, HEIC, TIFF) и **допсоглашения в Word** отправляются в Google Gemini. Только Gemini умеет распознать скан и разобрать свободные формулировки вроде «пункт 5.3 изложить в следующей редакции…».
  - Отправку можно отключить галочкой на вкладке «Итоговая редакция».
  - Без Gemini допсоглашения в Word разбираются по типовым формулировкам, а сканы обработать не получится.
- Для конфиденциальных договоров используйте ключ из проекта Google AI Studio с включённой оплатой. На бесплатном тарифе Google может использовать отправленные данные для улучшения своих сервисов.

## Ключ Gemini

Ключ хранится в файле `.env` рядом с программой. Файл исключён из git, права у него `600`. Указать ключ можно двумя способами:

- в окне **⚙ Настройки** программы. Ключ уйдёт только на локальный сервер программы, а в окне будет видно лишь «задан / не задан»;
- в Терминале, без отображения ключа на экране:

```bash
read -rs "KEY?Ключ Gemini: " && printf 'GEMINI_API_KEY=%s\n' "$KEY" > .env && chmod 600 .env && unset KEY
```

Модель по умолчанию — `gemini-3.8-flash`. Другую модель можно указать в настройках или строкой `GEMINI_MODEL=…` в `.env`.

## Итоговая редакция: как пользоваться

1. Загрузите исходный договор (.docx).
2. Перетащите изменяющие документы, можно несколько сразу.
   - Документы применяются по дате, протокол без даты — первым. Порядок можно поменять стрелками.
   - Поле с названием документа — это автор правок в Word.
3. Проверьте таблицу правок. Каждую правку можно отключить, исправить номер пункта, действие или текст, а также добавить правку вручную. Статус показывает, нашла ли программа пункт в договоре:
   - зелёный — найден по номеру;
   - жёлтый — найден по тексту, проверьте;
   - красный — не найден, такая правка не применится.
4. Нажмите «Собрать итоговую редакцию». Файл сохранится в «Загрузки» и в историю.

Предупреждения, на которые стоит обратить внимание:

- **Номера набраны текстом.** После вставки или исключения пункта следующие номера сами не сдвигаются. Программа предупредит о дублях.
- **Перекрёстные ссылки.** Если пункт, на который есть ссылка («см. п. 6.19»), сменил номер или исключён, программа предупредит. Сами ссылки она не исправляет.
- **В договоре уже есть правки.** Они остаются в файле, а изменения применяются к принятой редакции.

## История

Каждый прогон сохраняется в папку `Архив/ГГГГ-ММ-ДД_ЧЧММСС_<договор>/`:

- `вход/` — копии исходных файлов;
- `результат/` — готовый документ и распознанный текст сканов;
- `отчёт.md` — какие правки применены, а какие нет;
- `meta.json` — служебные данные.

Папка `Архив` исключена из git. Удалять старые прогоны нужно в Finder.

## Требования к шаблону протокола

- Поля вида `{{название договора}}`: программа найдёт их сама и покажет для заполнения.
- Таблица из 3 колонок с заголовком «Редакция …» (№ пункта / Редакция Стороны-1 / Редакция Стороны-2): в неё добавляются строки с пунктами.
- Шаблон ищется в папке программы, затем в `docs/`.

## Как оформляются пункты в протоколе

- Новый пункт: в колонке Стороны-1 «Отсутствует».
- Удалённый пункт: в колонке Стороны-2 «Исключить».
- Если контрагент разбил или объединил пункты, они выводятся одной строкой, например «7.2 (7.2, 7.3 в редакции Стороны-2)».
- Добавленный текст выделяется жирным в колонке Стороны-2.
- Изменения только форматирования и правки в сносках не учитываются.

## Для разработки

- Тесты: `python3 -m unittest discover tests`.
- Живой тест Gemini на синтетическом тексте: `RUN_GEMINI=1 python3 -m unittest discover tests -k Live`.
- Архив в другую папку (для проверок): `ARCHIVE_DIR=/путь python3 protocol_app.py`.
